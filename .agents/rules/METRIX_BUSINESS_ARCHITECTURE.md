# METRIX Project Rules & System Architecture

This document serves as the permanent memory, architectural blueprint, and strictly enforced system rules for the MetrixMedia business and its digital infrastructure.

## 1. Business Model & Core Identity
**Identity:** Metrix is NOT a traditional marketing agency or hardware seller. We are a **B2B SaaS / Customer Data Platform (CDP)** operating in the **O2O (Online-to-Offline) Commerce** industry.
**Elevator Pitch:** "Metrix is the In-Store Operating System for independent hospitality. Aggregators like Talabat and Deliveroo tax local venues up to 32% and steal their customer data. We deploy luxury tabletop hardware and intelligent software that allows independent venues to reclaim their diners, capture first-party WhatsApp databases, and drive direct repeat orders at zero commission."
**Core Market Focus:** **100% Focused on Dubai, UAE (GCC)**. Target corridors: Jumeirah (1, 2, 3), Al Wasl Road, DIFC, Downtown Dubai, Dubai Marina, and Business Bay. Focus niches: High-AOV specialty coffee roasters, shisha lounges, boutique bistros, artisan pizzerias, and luxury aesthetic clinics.
**Core Value Proposition:** To eliminate cross-border shipping friction, customs delays, and courier overhead (₹9,400+ per parcel), METRIX operates with **100% Digital Delivery**. We deliver bespoke, 300 DPI ultra-high-resolution print-ready digital vector assets (PDF/SVG) engineered to upgrade existing venue tabletop touchpoints (100mm × 155mm acrylic standees, wooden clips, table tents, and check presenters). The tabletop asset acts as the high-dwell-time anchor for customer interaction (while guests wait for food or the bill), while the real business model is the recurring SaaS revenue generated by our software (VIP data capture, real-time dining recovery, and direct-ordering engines). Venues can print and slide the assets into their tables in under 60 seconds.

## 2. Core Project Files & Data Pipeline
The frontend infrastructure allows the user to generate, preview, and download custom digital assets.
* **`sales.html`**: The monolithic control center. Configures campaigns (business name, styling) and pushes generated campaigns directly into the Supabase database. Features a "Master Standee" button in the top navigation that opens a generic `flyer.html` in a new tab, where the QR code is hardcoded to route to `live.html` (the Master Demo Redirector).
* **`portal.html`**: The interactive "Digital Demo" portal that simulates the client's mobile experience. Features a premium "Unlock VIP Privileges 🥂" gate for 5-star ratings and a private negative feedback gate for 1-3 stars. BOTH gates capture Name, Phone, and Date of Birth (DOB) and send this data to custom Google Sheets webhooks.
* **`live.html`**: The Master Demo redirector. Scanned physical standees hit this URL, which queries the Supabase `campaigns` table for the most recent entry and dynamically redirects the user to the custom generated `portal_url`. The loading screen mirrors the premium portal UI to ensure a seamless transition.
* **`flyer.html`**: The physical print asset generator. Strictly sized for 100mm x 155mm acrylic standees. It utilizes a resilient `@media print` layout that rotates the vertical standees -90 degrees and stacks them vertically on standard A4 portrait paper to completely bypass printer hardware clipping.
* **`assets_generator.html`**: The 12-carousel direct-response design studio. Generates uncompressed 1080p slide carousels across the 4 psychological funnel stages (Attention/Problem, Future Imagination, Threshold Engineering, Action/CTA) with copy-pasteable marketing captions.
* **`demo.html`**: The live interactive simulation sandbox. Allows clients to test both positive (VIP handshake) and negative (instant manager WhatsApp alert) feedback flows.

## 4. Strict Coding Rules & Technical Guidelines
- **Business Names**: Dom elements representing the business name capsule use class `.biz-title-placeholder` (typically inside `.standee-header h2`). Do NOT overwrite this with the custom flyer headline.
- **Headline Text**: Custom flyer headlines must strictly target `.standee-body h3` (not the general h2 tags in headers).
- **Campaign Config Scope**: Campaign styling data includes `theme`, `font`, `logo`, `qrSettings` (`qrDotStyle`, `qrCornerStyle`), and `flyerSettings` (`flyerHeadline`, `flyerSub`, `flyerFooter`, `flyerTextStyle`).
- **No Keystroke Reloads**: Never dynamically reassign iframe `src` URLs on text input changes or keystrokes. This causes page flicker, resets states, and drops payload messages.
- **Iframe Initialization**: Set the iframe `src` once during initial page load or when the campaign type changes.
- **Real-time Sync**: Apply all text, color, font, and theme changes instantly using window `postMessage` (`type: 'UPDATE_FLYER'`).
- **Print Media Queries**: Ensure `@media print` CSS rules preserve theme backgrounds, gradients, and images. Use `-webkit-print-color-adjust: exact !important`.
- **Print Dimensions & Scaling**: Do not alter the 100mm x 155mm hardcoded sizing in `flyer.html` or the rotational `@media print` architecture, as this guarantees a 1:1 hardware fit on A4 paper regardless of the printer model used.
- **No `canvas` for QR Codes on Mobile**: The QR code rendering must always use `type: "svg"` with an injected `viewBox` attribute. Canvas rendering on mobile browsers is unreliable for complex strings.
- **No CORS Blocks**: External API calls for URL shortening MUST be routed through a CORS proxy (e.g., `allorigins.win`) to prevent browser fetch blocking on Vercel.
- **Live Deployment Updates**: Any edits made to `portal.html` or `portal.js` must be pushed to GitHub to take effect on the live hosted site. Always bump the cache-buster string (e.g., `?v=2.4`) in `portal.html` when updating `portal.js` to clear mobile caches.
- **3-Color Infinite Customization Engine (The Master Layout)**: Static CSS themes have been permanently deleted. The system now uses the structure of the "Premium Matte Black" (`theme-onyx`) design as the unbreakable Master Layout for all flyers.
  - **No Dark Vignettes**: The `.standee-face` must have `box-shadow: none !important` to ensure custom background colors never look muddy or mixed.
  - **Dynamic Metallic Gradients**: The user configures 3 colors via URL parameters: `flyerBg` (Background), `flyerAccent` (Primary Headline & QR Code), and `flyerText` (Secondary text).
  - **Preserving Depth**: The `flyerAccent` color is dynamically converted into a 3-stage metallic `linear-gradient` in JS to ensure the headline text always looks premium and "two-tone", preventing flat/cheap solid colors.
  - **The Default Baseline**: If no colors are provided, the system perfectly defaults to the user's favorite Matte Black standard (`#0a0a0a` background, `#d4af37` gold metallic accent, `#ffffff` white text). Never alter this foundational baseline structure.
- **Stateful QR Code Architecture**: Never encode large data strings (like portal URLs with styling parameters) directly into QR codes, as this generates messy, unreadable, dense grids. All generated flyers must strictly encode a short routing URL containing a database ID (e.g., `metrixmedia.agency/live.html?id=17382`). The `live.html` router acts as a universal dynamic redirector—it intercepts the scan, fetches the campaign's `portal_url` from Supabase using the provided ID, and executes the redirect instantly.

## 6. The D2C Ordering Engine (Anti-Aggregator Playbook)
Metrix has evolved beyond review capture into a full **Zero-Commission Direct Ordering Gateway** for F&B. The core strategy is a "Judo" attack against Zomato/Swiggy.
- **The Trojan Horse (Acquisition):** Restaurants staple Metrix QR flyers to outgoing aggregator delivery bags ("Scan for 20% off direct next time") to hijack Zomato's customers and funnel them into the Metrix WhatsApp ordering database.
- **White-Label B2C UI (The Ghost Brand):** To the end-consumer, the ordering portal is 100% branded as the Restaurant (e.g., "Cafe Mocha VIP"). Metrix remains invisible except for a tiny *"Powered by Metrix"* trust badge at the footer (designed to drive B2B viral loops from visiting cafe owners).
- **Financial Architecture (Zero Legal Liability):** Metrix NEVER touches the principal transaction funds to avoid RBI Payment Aggregator compliance. The checkout flow routes UPI payments *directly* to the restaurant's bank account instantly. Metrix bills the restaurant post-paid (SaaS fee + transaction usage) via an AWS-style invoice.
- **Logistics Integration (The Ghost Fleet):** Metrix software integrates with white-label delivery APIs (Shadowfax, Borzo, Porter). Instead of the restaurant paying 30% to Zomato, they pay a premium flat fee (e.g., ₹80) directly to the gig-rider. Result: Restaurant nets more profit, Rider gets paid double, and Metrix takes zero variable delivery risk while remaining a high-margin software company.
